# Daily Notes: 2026-07-31

## GPU Crash Investigation (llama.cpp)
- **Symptom**: Both GTX 1070s crashing (TDR `0xC0E90002` "GPU is lost") when launching Qwythos 9B MTP.
- **Root Cause**:
  1. `start-qwythos-server.ps1` defaulted to `q8_0` KV cache. At 65536 context, `q8_0` KV cache alone requires ~4.6 GB of VRAM. Combined with the 5.48 GB model weights and 310 MB MTP draft context, it required ~10.4 GB of VRAM, exceeding the 8 GB available on a single GTX 1070.
  2. The script hardcoded `-ngl 99`, which prevented `llama.cpp`'s internal VRAM fit algorithm (`--fit-target`) from automatically reducing layers to prevent OOM.
  3. The `start-qwythos.ps1` script erroneously overrode the dual-GPU configuration to use only GPU 1 (`$CudaDevices = @("1")`), limiting VRAM to 8 GB instead of the available 16 GB combined.
- **Fixes Applied**:
  - **KV Cache**: Changed default KV cache to `q4_0` (reduces KV cache size by 50%, e.g., to ~2.3 GB at 64k ctx).
  - **CUDA Graphs**: Added `GGML_CUDA_DISABLE_GRAPHS=1` to prevent hidden inference-time buffer spikes.
  - **Topology**: Restored dual-GPU assignment (`$CudaDevices = @("1","2")`) for Qwythos in `start-qwythos.ps1` to utilize 16 GB combined VRAM.
  - **VRAM Reservation**: Replaced `-ngl 99` with `-ngl 999` to allow llama.cpp to clamp layers. Defaulted `$FitTargetMiB` to `1024` to ensure ~1 GB reservation per GPU for driver and compute buffers. Fixed tensor-split calculation to distribute weights based on actual usable VRAM (free VRAM minus reservation).
- **Outcome**: The `standard` profile (64k context, MTP) now comfortably fits within the 16 GB combined VRAM of the two GTX 1070s.
